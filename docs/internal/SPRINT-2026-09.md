## 0. How to use this runbook

### A. Two machines, one rule

| | **prod** | **lab** (new, provisioned Day 0) |
|---|---|---|
| Host | `152.53.113.104`, `ssh dev@152.53.113.104` | new VPS, `ssh dev@LAB` |
| Runs | five validators, indexer/explorer/faucet/keeper, nginx/TLS, the factory | builds, dev nodes, test conversion, load generation, red-agent, all parallel Claude Code sessions, evidence |
| Touched during sprint | **three times only**: baseline snapshot (Day 0), runtime upgrade to 307 (Day 3), site redeploy (Day 4); plus read-only health checks | continuously |
| Secrets | sudo key, faucet seed, factory API key, validator keystores | a lab API key and throwaway dev keys only |

Why: prod is one VPS carrying the whole public chain. A `cargo build`, a flood test, or six Claude Code sessions on that box is the fastest way to lose the testnet the week of the meeting. Separating the machines also removes prod as a single point of failure for *your work*: if prod needs a reboot you keep working; if lab dies, prod is untouched and everything on lab is in git.

### B. Persistence rules — the laptop is never a dependency

- Every long-running process is a Docker container with `restart: unless-stopped`, a systemd user unit, or a command inside a **named tmux session** with output piped to a log file.
- Every Claude Code session runs inside its own tmux session, in its own **git worktree**, with a written brief. Reconnect: `ssh dev@LAB` → `tmux ls` → `tmux attach -t <name>` (detach: `Ctrl-b d`). Resume the agent in that worktree with `claude --continue` (confirm the flag with `claude --help` on your installed version).
- Code lives in the repo (push every branch at least twice a day). Evidence lives in a private `scalar-evidence` repo, committed after every task. Config that is not in git today (systemd drop-ins) gets copied into the evidence repo on Day 0.
- Secrets never leave prod. Lab cannot sign anything on the public chain except with throwaway faucet-funded test keys.

### C. Evidence protocol (identical for every task)

```
~/evidence/<dayN>/<NN-task-slug>/
  README.md    # what, when (UTC), machine, exact command(s), result, links (issue/PR/block/tx)
  *.log        # raw output — always `| tee` into here
  *.json       # raw RPC/API responses where relevant
```
```bash
cd ~/evidence && git add -A && git commit -m "<dayN>/<NN-task>: <one line>" && git push
```
The Day 5 scorecard is assembled from these directories. If it is not in `~/evidence`, it did not happen.

### E. Do-not-change list (whole sprint)

1. `construct_runtime!` pallet order/indices — changes break storage decoding.
2. Chain spec `id`, genesis, `protocolId`, chain name — any of these is a new chain or a coordinated five-node restart. Post-meeting.
3. `EraDuration`, `UnstakeCooldown`, `SupplyCap`, `MinStake`, `MaxStakePerAgent`, emission constants, staking constants — on the public chain. They are compressed **only** on the `lab/compressed-timing` branch, which is never merged.
4. Sudo key: no rotation, no removal (D1). Alice must never be sudo on prod.
5. Nothing submits to `wss://rpc.scalarnet.io` from lab except (a) the tester-guide smoke flow with fresh faucet keys and (b) the repo's own economic-gate harness. No floods, no red-agent, no bulk registration.
6. CI: no weakening of checks, no `strict:false`, no removal of `secrets`/`chainspec` from required checks.
7. ufw, nginx, TLS, DNS on prod — untouched.
8. RPC ports 9944–9948 stay loopback-only; `--rpc-methods safe` stays on all five validators.
9. Storage layouts of existing items — only additive storage in this sprint (see E18/E2 design), no field changes to existing structs, no migrations.
10. The keeper timer.
11. No validator restarts unless a task here says so, and then rolling, then restart the three products (#155).

### 0.1 Provision the lab VPS

**What.** A second VPS: Ubuntu 24.04, ≥ 8 vCPU, ≥ 32 GB RAM, ≥ 300 GB SSD (Rust worktrees are large; six of them can pass 100 GB). Same provider (netcup) is fine; any provider is fine.
**Why.** Prod must not build, flood, or host agents (§A).
**Where.** Provider console → then `ssh root@LAB`.
**Steps.**
1. Add your SSH public key at provisioning time. Note the IP as `LAB` below; put it in your SSH config:
   ```
   # ~/.ssh/config (laptop and phone client)
   Host lab
     HostName <LAB_IP>
     User dev
     ServerAliveInterval 30
   Host prod
     HostName 152.53.113.104
     User dev
     ServerAliveInterval 30
   ```
2. Create the `dev` user, copy the key, enable sudo:
   ```bash
   adduser --disabled-password --gecos "" dev && usermod -aG sudo dev
   mkdir -p /home/dev/.ssh && cp ~/.ssh/authorized_keys /home/dev/.ssh/
   chown -R dev:dev /home/dev/.ssh && chmod 700 /home/dev/.ssh && chmod 600 /home/dev/.ssh/authorized_keys
   passwd dev            # interactive sudo password, stored in your password manager
   loginctl enable-linger dev
   ```
3. **From a second terminal**, prove `ssh dev@LAB` works with the key. Only then harden sshd (same rule as prod: never disable an auth path without a proven alternative):
   ```bash
   sudo sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/; s/^#\?PermitRootLogin .*/PermitRootLogin no/' /etc/ssh/sshd_config
   sudo systemctl restart ssh
   ```
4. Firewall — inbound SSH only. Dev nodes only ever bind to `127.0.0.1` on the host:
   ```bash
   sudo ufw default deny incoming && sudo ufw default allow outgoing && sudo ufw allow 22/tcp && sudo ufw --force enable
   ```
**Verify.** `ssh lab` works from the laptop; `sudo ufw status numbered` shows only 22; `loginctl show-user dev | grep Linger` → `Linger=yes`.

### 0.5 tmux layout script and log capture

**What.** One idempotent script that (re)creates every named session and pipes each to a log.

```bash

#!/usr/bin/env bash
# Idempotent: creates missing sessions, never kills existing ones.
set -euo pipefail
mkdir -p "$HOME/evidence/logs"
mk() {  # mk <session> <dir>
  if ! tmux has-session -t "$1" 2>/dev/null; then
    tmux new-session -d -s "$1" -c "${2:-$HOME}"

mk op     "$HOME/scalar-commons-v4"                                   # you: fixes, reviews, merges

  mk "$s" "$HOME/wt"
done
tmux ls
EOF
```

### 2.1 E18 + E2 — design (additive storage, no migration)

**What.** Provider consent for agreements and a way out of stuck ones, without changing any existing struct.
**Why.** Today any registered buyer can pin any agent's `activeEscrowCount` for ~10 CMN and the agent cannot unstake for up to 14 days (E18); a non-delivered agreement has no exit except dispute + 14 days (E2). Additive storage means no migration — the one risk you cannot afford this week.

Design (write it into `pallets/escrow/DESIGN-E18-E2.md` before coding):

| Element | Change |
|---|---|
| New storage | `PendingAcceptance: StorageDoubleMap<buyer, (provider, seq), created_at: BlockNumber>` — an entry means "created, not yet accepted". Existing agreements have no entry and are treated as accepted (grandfathered). |
| `create_agreement` | Unchanged inputs. Reserves the buyer's funds as today; writes `PendingAcceptance`; does **not** increment the provider's `activeEscrowCount`; still counts toward `maxAgreementsPerPair` (so pending spam is capped and costs the attacker locked capital). |
| New `accept_agreement(buyer, seq)` (provider signs) | Removes the pending entry, increments the provider's `activeEscrowCount`, emits `AgreementAccepted`. The E1 capability check also runs here. |
| New `reject_agreement(buyer, seq)` (provider signs) | Removes the entry, unreserves the buyer, closes the agreement, emits `AgreementRejected`. |
| New `cancel_pending(provider, seq)` (buyer signs) | Same as reject but buyer-initiated, only while pending. |
| `record_delivery` | `ensure!(!PendingAcceptance::contains_key(..), Error::NotAccepted)`. |
| New `expire_agreement(buyer, provider, seq)` (anyone signs) | Modelled on `oracle.expire_request`: `ensure!(now > deliver_by + T::ExpiryGrace::get())`, `ensure!(no delivery recorded)`, refund the buyer, decrement both counts, close, emit `AgreementExpired`. `ExpiryGrace` = 10 blocks. |
| `request_unstake` | Unchanged — pending agreements no longer count, so E18 is closed by construction. |
| Errors/events | Add only; rename nothing. |
| SDK | `acceptEscrow` currently maps to `recordDelivery`; add `acceptAgreement` and have the reference agent call accept → deliver. |

**Personal.** The design and the decision. Post it in the issue before writing code.
